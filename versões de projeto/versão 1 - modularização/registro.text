Na versão do livro o node não tem 100% de suporte ao ES6, então é usado um módulo que emula recursos interessantes. E é usado o Babel, que é um Transpiler.
O que é um transpiler?
Ele converte um código de javascript moderno para um código de versões antigas que possam ser lidos ler, por exemplo:

### JS Moderno ###
const somar = (a, b) => a + b;

### JS Antigo ###
var somar = function(a, b) {
    return a + b;
};

npm install  babel --save

###Implementando um recurso Estático###
O padrão de desenvolvimento de uma API REST trabalha em cima do conceito de criação e manipulação de recursos. Esses recursos são entidades da aplicação utilizada 
para consulta, atualizar e excluir dados. Tudo é baseado em manipular dados de um recurso.

Por exemplo, nessa aplicação o recurso principal será a entidade tarefas, que será acessada pelo endpoint "/task". Esta entidade terá alguns dados que descreverão
que tipo de informação será mandito nesse recurso.

###Código###
import express from "express";
const PORT = 3000;
const app = express();

app.set("json spaces", 4); // faz com que o resultados retornem um JSON formatado

app.get("/", (req,res) => res.json({status: "NTask API"}));

app.get("/tasks",(req,res)=>{
    res.json({
        task:[
            {title: "Fazer compras"},
            {title: "Consertar o pc"},
        ]
    });
});

app.listen(PORT, ()=> console.log(`NTask API - porta ${PORT}`));

Organizando o carregamento dos módulos.

Será usado o padrão MVR(Model-View-Router) para organizar a aplicação de forma simplificada. Ela evita a necessidade de ter todos os endpoints em um único arquivo.
O módulo consign permite carregar e injetar dependências de forma bem simples. Aparentemente, a biblioteca consign parece ser mais do mesmo pois o javascript já possui
um sistema de módulos. Entretanto, a biblioteca consign oferece uma camada de automação e facilitando a escrita do código. 

consign()                ---->	     Inicializa o Consign.
.include("routers")	     ---->       Indica a pasta que contém os módulos que devem ser carregados.
.into(app)	                         Integra os módulos carregados à aplicação Express.

---------------------------------------------------------------------------------------------------------------------------------------------------------------------

###Se a api crescer e tenha 30 arquivos de rotas, você vai precisar fazer o seguinte:

import usuarios from "./routers/usuarios.js";
import tarefas from "./routers/tarefas.js";
import projetos from "./routers/projetos.js";
import comentarios from "./routers/comentarios.js";
import autenticacao from "./routers/autenticacao.js";

usuarios(app);
tarefas(app);
projetos(app);
comentarios(app);
autenticacao(app);

###Com consign, você faria:

const express = require('express');
const consign = require('consign');

const app = express();

consign({ verbose: false })
  .include('db.js')
  .then('models')
  .then('associations.js')
  .then('auth.js')
  .then('middlewares.js')
  .then('routes')
  .then('boot.js')
  .into(app);

module.exports = app;

###CÓDIGO ESCRITO NO ARQUIVO TASKS DO DIRETÓRIO MODELS###

module.exports=app=>{
    return{
        findAll:(params, callback)=>{
            return callback ([
                {title: "Fazer Compras"},
                {title: "Consertar o PC"},
            ]);
        }
    };
};

Esse modelo inicialmente terá apenas uma função tasks.findAll() que receberá dois argumentos como parâmetro: params e callback. A variável params não será utilizada
no momento, mas ela servirá de base para enviar alguns filtros de pesquisa SQL, algo será abordado nos próximos capítulos. Já o segundo argumento é a função de 
callback que retorna de forma assícrona um array stático de tarefas.

Para chamá-lo dentro de routers/task.js, você terá de carregar esses modelos por meio da variável app. Afinal, os módulos de diretórios inseridos na função consign()
injetam suas lógicas dentro dessa variável principal da aplicação.

###CÓDIGO ESCRITO NO ARQUIVO TASKS DO DIRETÓRIO ROUTERS### -> FOI TUDO MODIFICADO.

module.exports=app=>{
    const Tasks=app.models.tasks;
    app.get("/tasks",(req,res)=>{
        Tasks.findAll({},(tasks)=>{
            res.json({task:tasks});
        });
    });
};

A pasta libs/middlewares.js será responsável por carregar toda a lógica dos middlewares e configurações específicas do express.
Crie o arquivo libs/middlewares e escreva o código abaixo:

module.exports=app=>{
    app.set("port", 3000);
    app.set("json spaces", 4);
};

Crie o arquivo libs/boot.js e escreva o código abaixo:
A pasta libs/boots.json será responsável por iniciar o servidor através da função app.listen().
module.exports=app=>{
  app.listen(app.get("port"),()=>{
    console.log(`NTask API - porta ${app.get("port")}`);
  });
}

vá no arquivo princicpal index.js e edite novamente:

import express from "express";
import consign from "consign";

const app = express();

consign()
.include("models")
.then("libs/middlewares.js")
.then("routes")
.then("libs/boot.js")
.into(app);

Para testar essas novas alterações, reinicie o servidor e acesse novamente o endpoint: http://localhost:3000/tasks
