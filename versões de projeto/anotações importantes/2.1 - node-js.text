
CARACTERÍSTICAS DO DO EXPRESS:
- routing robusto --> sistema que decide qual código será executado de acordo com a requisição.
- facilmente integrado com os principais templates engines --> páginas html dinâmicas criadas no lado servidor. 
- conceito de middlewares ---> função que processa a requisição http.
- Possui uma grande lista de middlewares 3rdd-party ---> serviços externos, serviços de terceiros, que processam uma requisição http.
- Content negotiation ---> define qual o tipo de dado que está na requisição ou no response. Por exemplo: Content-Type: application/json.
- Adota padrões e boas práticas de serviços REST. ----> padronização de como as api serão orgazinadas.

1. Routing robusto
Conceito: routing é o sistema responsável por determinar qual código será executado de acordo com a requisição recebida pelo servidor.

No Express, podemos definir rotas com diferentes métodos HTTP, parâmetros e caminhos.

Por exemplo:
const express = require('express');
const app = express();

app.get('/usuarios', (req, res) => {
    res.send('Lista de usuários');
});

app.get('/usuarios/:id', (req, res) => {
    res.send(`Usuário ${req.params.id}`);
});

app.listen(3000);


Nesse código:
- GET /usuarios retorna uma mensagem com a lista de usuários.
- GET /usuarios/10 retorna Usuário 10.
- :id é um parâmetro dinâmico, acessível por req.params.id.
Por que o routing é robusto?

Porque o Express oferece recursos para organizar e controlar rotas, incluindo parâmetros, diferentes métodos HTTP, agrupamento com express.Router() e integração 
com middlewares.

Inclusive, você já utilizou o express.Router() no seu projeto de cursos para separar as rotas do arquivo principal.

2. Facilmente integrado com os principais template engines
Conceito: um template engine permite gerar páginas HTML dinamicamente, inserindo informações variáveis em um modelo predefinido.

Imagine que você tenha um sistema de cursos e queira exibir o nome de cada curso em uma página.

Sem um template engine, você poderia construir o HTML manualmente. Com um template engine, cria um modelo HTML e fornece os dados que devem aparecer nele.

Exemplo conceitual com EJS:
app.set('view engine', 'ejs');

app.get('/curso', (req, res) => {
    res.render('curso', {
        nome: 'Node.js'
    });
});


O arquivo views/curso.ejs poderia conter:
<h1>Curso de <%= nome %></h1>


O resultado enviado ao navegador seria:
<h1>Curso de Node.js</h1>


O Express permite trabalhar com mecanismos como EJS, Pug e Handlebars, desde que estejam instalados e configurados adequadamente.

Quando isso é útil?
- Sistemas com páginas dinâmicas.
- Painéis administrativos.
- Sites que renderizam HTML no servidor.
Observação: se você estiver construindo uma API REST que retorna apenas JSON para um frontend independente, normalmente não precisará de um template engine.

3. Conceito de middlewares
Conceito: um middleware é uma função que participa do processamento de uma requisição HTTP, podendo executar alguma tarefa, modificar a requisição ou a resposta, 
encerrar o processamento ou encaminhá-lo para a próxima etapa.

Veja este exemplo:
const express = require('express');
const app = express();

app.use((req, res, next) => {
    console.log('Uma requisição foi recebida');
    next();
});

app.get('/', (req, res) => {
    res.send('Página inicial');
});

app.listen(3000);


O fluxo é:
1. Requisição HTTP

O navegador solicita /

2. Middleware

Executa o console.log()

3. next()

Permite continuar o processamento

4. Rota GET /

Envia a resposta ao cliente


O next() é importante porque, nesse exemplo, ele permite que o processamento continue até a rota seguinte.

Se o middleware enviar uma resposta e não chamar next(), o fluxo normal não continuará para a próxima etapa.

Os middlewares podem ser usados para:
- Verificar autenticação.
- Registrar requisições.
- Interpretar o corpo de uma requisição JSON.
- Validar dados.
- Tratar determinados erros.


4. Grande lista de middlewares de terceiros
Conceito: o Express possui middlewares próprios, mas também pode ser ampliado por pacotes criados por outros desenvolvedores.

Esses pacotes são chamados de third-party middleware — middlewares de terceiros.

Por exemplo:
Middleware	Finalidade
cors	Configurar o compartilhamento de recursos entre origens diferentes
morgan	Registrar informações sobre as requisições HTTP
helmet	Configurar cabeçalhos HTTP relacionados à segurança
express-rate-limit	Limitar a frequência de requisições

Um exemplo de utilização:
const express = require('express');
const cors = require('cors');

const app = express();

app.use(cors());

app.get('/usuarios', (req, res) => {
    res.json([
        { id: 1, nome: 'Ana' },
        { id: 2, nome: 'Carlos' }
    ]);
});

app.listen(3000);


Nesse exemplo, o cors é um pacote externo integrado ao Express por meio de app.use().

A vantagem: você não precisa desenvolver do zero funcionalidades comuns a diversas aplicações.

Importante: instalar um middleware não garante automaticamente a segurança da aplicação. É necessário configurá-lo de acordo com o cenário.


5. Content negotiation
Conceito: content negotiation, ou negociação de conteúdo, é o mecanismo pelo qual cliente e servidor podem negociar o formato da representação de um recurso.

Por exemplo, um cliente pode indicar que prefere receber JSON:
GET /usuarios/1 HTTP/1.1
Host: localhost:3000
Accept: application/json


O cabeçalho Accept informa quais tipos de conteúdo o cliente aceita.

Uma resposta possível seria:
HTTP/1.1 200 OK
Content-Type: application/json


{
    "id": 1,
    "nome": "Ana"
}


O Express oferece o método req.accepts() para verificar quais tipos de conteúdo são aceitos pelo cliente.

Exemplo:
app.get('/usuarios/:id', (req, res) => {
    if (req.accepts('json')) {
        return res.json({
            id: req.params.id,
            nome: 'Ana'
        });
    }

    res.status(406).send('Formato não aceitável');
});


Nesse caso, a aplicação verifica se o cliente aceita JSON e responde de acordo.

Uma ressalva: o Express não negocia automaticamente todos os formatos de toda resposta. O desenvolvedor precisa implementar a lógica necessária.

Quando isso é útil?

Quando uma aplicação precisa disponibilizar representações diferentes de um recurso, como JSON ou HTML, dependendo das capacidades ou preferências do cliente.


6. Adota padrões e boas práticas de serviços REST
Conceito: REST é um estilo arquitetural para sistemas distribuídos. Ele orienta como organizar recursos e suas operações por meio de uma interface uniforme.

O Express facilita a criação de APIs que seguem essas ideias, mas não transforma automaticamente qualquer aplicação em uma API REST.

Imagine uma API de usuários:
Método HTTP	Endpoint	Operação
GET	/usuarios	Listar usuários
GET	/usuarios/10	Consultar um usuário
POST	/usuarios	Criar um usuário
PUT	/usuarios/10	Substituir um usuário
PATCH	/usuarios/10	Atualizar parcialmente um usuário
DELETE	/usuarios/10	Excluir um usuário

No Express, essas operações podem ser implementadas assim:
app.get('/usuarios', listarUsuarios);

app.get('/usuarios/:id', buscarUsuario);

app.post('/usuarios', criarUsuario);

app.put('/usuarios/:id', substituirUsuario);

app.patch('/usuarios/:id', atualizarUsuario);

app.delete('/usuarios/:id', excluirUsuario);


Os nomes listarUsuarios, buscarUsuario e os demais representam funções que você precisaria implementar.

Observe a lógica: usamos o recurso /usuarios e diferenciamos as operações pelos métodos HTTP, em vez de criar endpoints como /listarUsuarios, /criarUsuario 
e /excluirUsuario.

Outras boas práticas incluem:
- Utilizar códigos de status HTTP apropriados, como 200, 201, 204, 400 e 404.
- Manter uma estrutura consistente nas respostas.
- Validar os dados recebidos.
- Separar responsabilidades entre rotas, controllers e a camada de acesso aos dados.
- Projetar operações de maneira compatível com as restrições do REST, como a comunicação stateless.

Vamos conectar tudo isso ao seu aprendizado de Node.js
Uma forma de entender essas seis características é pensar em uma API de agenda de contatos, semelhante à que você já desenvolveu:
Routing

Define os caminhos para pesquisar, criar, editar e excluir contatos.



Middlewares

Verificam dados, interpretam JSON e registram requisições.



Middlewares de terceiros

Acrescentam recursos usando pacotes do ecossistema Node.js.



Template engines

Geram páginas HTML dinâmicas, caso a aplicação precise delas.



Content negotiation

Permite decidir qual representação enviar conforme o que o cliente aceita.



REST

Organiza os endpoints em recursos e utiliza os métodos HTTP adequados.



Minha observação: para aprofundar Node.js, vale dominar especialmente routing, middlewares e o ciclo de requisição e resposta. Esses conceitos são fundamentais 
para compreender como uma aplicação Express é estruturada e como uma requisição passa pelo sistema.

O Express fornece ferramentas para implementar essas funcionalidades; a arquitetura e a qualidade final da aplicação dependem de como você as utiliza.
